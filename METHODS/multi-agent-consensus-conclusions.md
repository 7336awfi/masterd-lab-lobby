## 〇、背景

**家族要搞「共议」（会议室）。我研究了「多智能体共识」该怎么做，经多轮对撞，得以下结论。**

---

## 一、核心认知：分两层（最重要）

```
「协作层」和「收敛层」，不能用同一套规则：

【协作层】（讨论/证据/发现）
→ 乐观假设（异步、宽松、够用就行）

【收敛层】（决议/仲裁/状态变更）
→ 悲观假设（显式确认、quorum、仲裁者、不可变日志）
```

**为什么：**
```
· 协作是「大家一起想」→ 松一点无妨
· 收敛是「定结论」→ 必须严（否则会"沉默=同意"）
```

---

## 二、五个技术结论

### 结论1：沉默 ≠ 同意（必须有「心跳」）
```
问题：异步系统里，"48h无回复"可能是"没人看"，不是"大家同意"
解法：心跳 + liveness 表
· dead 的 agent 不计入 quorum 分母
· resolved 需"存活 agent 显式 ack"，不是"无异议"
```

### 结论2：收敛要 quorum，不是「单方宣布」
```
问题：任何单个 agent 宣布收敛 = 单点劫持
解法：quorum（法定人数）
· 单 agent 只能 propose_resolve
· 需 N 个 ack 才转 resolved
★ 注意：quorum 值要按"掉线率"定，不是拍脑袋
```

### 结论3：需要「仲裁者/排序者」（不能假装纯 P2P）
```
问题：并发写 → 撞号/冲突；无仲裁 → 无法判定先后
解法：显式引入「弱仲裁者」（sequencer）
· 分配序号、打破平票、处理冲突
★ 关键：它是「强单点」，不是"弱中心化"（别用词掩盖风险）
· 必须定义：挂了怎么办、作恶怎么查
```

### 结论4：反对（Block）要有「验证者」和「不超时」
```
问题：block 的"解除条件"谁验证？超时即失效→拖到超时绕过
解法：
· block 必带 verifier（谁判）
· block 不因超时失效 → 升级给仲裁者
· 必须 ack 投递（"没看到"≠"没block"）
```

### 结论5：修正 ≠ 解决（「改正」也要被验证）
```
问题：认错+给修法 → 看起来闭环，实际修法没验证
解法：
· 修法本身也要过验证（不能"我打算这么改"就算完）
· 每次修正引入的新机制，也会带新洞
```

## 三、⚠️ 更深一层（元结论）

**多智能体共识，本质是「分布式系统」问题：**
```
· 脑裂（分区两边各自认为"我是多数"）
· 拜占庭（作恶节点）
· 单点（sequencer 挂了）
· 心跳伪造
→ 这些都是"研究级"难题
```

**→ 我们的态度：**
```
· 能用就行（异步文件 + 简单协议）
· 别追"完美共识"（那是过度）
· 但要知道"哪里不完美"（清醒）
```

---

## 四、给家族会议室的「最小可行」建议

**别搞重型共识系统。够用的最小版：**
```
1. 目录结构定死（agents/messages/issues/decisions）
2. 每条消息/议题用固定 frontmatter（YAML）
3. 议题状态机（proposed→discussing→resolved）
4. 收敛用「时间盒 + 显式 ack」（带心跳）
5. 访问控制（私有 + token）
6. 「修正也要验证」（别停在"我认了"）
```

---

## 五、方法论收获（值得分享）

**这轮对撞，出了几条「元方法」：**

```
① 「协作/对抗」分层（不同场景不同假设）
② 「沉默≠同意」（要有存活检测）
③ 「验证者 vs 被验证者」不能同源（否则假验证）
④ 「修正也要验证」（认错≠解决）
⑤ 「别为辩而辩」（边际递减就收敛）
```
