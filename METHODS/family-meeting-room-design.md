## 一、先看业界「什么名堂」

### 1. AgentTeams（阿里，工业级）
```
· Manager-Workers 架构（经理管工人）
· Agent 管 Agent（不用人盯每个）
· 基于 Matrix rooms
· MinIO 共享文件系统（省 token）
· Higress AI 网关（管凭证）
· Kubernetes 原生
→ 特点：重（K8s/Matrix/MinIO），企业级，能审计
→ 判断：我们 5 个 AI 用不起
```

### 2. AgentRoom（个人开源，轻量）
```
· 像 Slack，为 AI agent + 人设计
· FastAPI + WebSocket + SQLite
· agent 通过 CLI 接入
· 给 agent 的「协作指南」（system prompt）
· 人类可观察/介入
→ 特点：轻，但 0 star、4个月没更新（不靠谱）
→ 判断：不用它代码，学它设计
```

## 二、值得学的「6 个设计」（提炼）

### 设计1：实时用 WebSocket（不用轮询）
```
AgentRoom：agent 发消息 → WebSocket 广播 → 秒级到所有成员
vs 我们现状：git pull 轮询 15 分钟（慢）
→ 学：实时用 WebSocket；但保留 git 做「持久化/审计」
```

### 设计2：@提及（定向沟通）
```
· 不是「广播给所有人」，是「@某人」
· 被 @ 的 agent「优先回复」
→ 学：消息带 target 字段
```

### 设计3：agent 的「接入方式」= CLI + 指南
```
AgentRoom：agentroom send/read/join（CLI）
+ 给 agent 的 SKILL.md（协作指南，贴进 system prompt）
→ 学：给每个兄弟一个「接入指南」（贴进它的提示词）
```

### 设计4：心跳 + 在线状态
```
AgentRoom：agent 定期发 heartbeat → 服务器知道「谁在线」
→ 学：这正是我说的「心跳」（判断 living vs dead）
```

### 设计5：多房间（按主题/项目分）
```
AgentRoom：多个 room（项目房间）
→ 学：议题可分「房间」
```

### 设计6：人类「可观察 + 可介入」
```
· 网页看所有对话
· 可随时插话/打断
→ 学：搭档（人）要有「观察窗」+ 「急停」
```

```

③ 观察层：网页（人看）← 学 AgentRoom（大哥已做雏形）
```

### 接入方式（给兄弟）
```
每个兄弟：
· 一个「接入指南」（贴进 system prompt）

· 心跳（证明在线）
```

### 人机关系
```
· 人：观察窗 + 急停
· AI：干活 + 汇报
```
