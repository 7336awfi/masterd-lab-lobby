## 一、射程声明（延续 v2）

**本方案解决「越权不可发生」，不解决「意图可验证」。**
```
· "意图可验证" → 开放语义不可判定 → 不解决
· "越权不可发生" → 可判定 → 解决（持续逼近）
```

**射程外：** 授权内作恶、意图语义、私钥窃取后冒充、量子攻击。

---

## 二、行业标准分层（v3 新增）

**关键：6 个标准不在同一层，别混着对齐。**

| 层 | 标准 | 作用 |
|---|---|---|
| **协议层** | **MCP**（Anthropic，事实标准） | 怎么传身份/授权 |
| **协议层** | IETF draft-klrc-aiagent-auth | 跟踪，别实现 |
| **协议层** | OAuth 智能体身份（Anthropic+OpenAI，2026.9.28） | 授权语义 |
| **治理层** | CSA Agentic Trust Framework (ATF, 2026.2) | 策略怎么定（零信任） |
| **身份根层** | DIF KYA-OS（DID + VC） | 身份从哪来（跨组织） |

**对齐优先级：**
```
必上：① MCP（协议）② 审计标准字段 ③ OAuth 智能体身份（预留）
按需：④ DIF KYA-OS（跨组织）⑤ CSA ATF（企业级）⑥ IETF（跟踪）
```

**DeepSeek 的一句话：**
> **「MCP 定协议，OAuth 定授权，审计 schema 定可观测。其余按业务触发。」**

## 四、五个模块（v3 更新）

### 模块1：身份与密钥
```
· Ed25519 密钥对（每 Agent 唯一）
· 私钥保管：硬件/进程级隔离（TPM/SE/TEE，或独立进程）
· ★ 身份根：内部用「公钥表」；跨组织时换 DIF/DID
```

### 模块2：授权（映射到 MCP）
```
· Capability 模型 → 表达成 MCP 的授权语义
· 约束维度：枚举（开放集，只承诺已枚举）
· 约束在「资源方」验证
```

### 模块3：策略（映射到 OPA）
```
· 用 OPA + Rego 写策略（标准策略引擎）
· 策略决策点（PDP）独立于 agent
· 策略可版本化（见审计的 policy_version）
```

### 模块4：人类批准（分层）
```
★ 关键：按「影响」分级，不按「频率」
· 只读/幂等 → 自动
· 写但可回滚 → 自动 + 事后审计
· 不可逆/高影响（转账/删除/外发）→ 人类批准
· 批准要带上下文（智能体身份+动作+资源+判定理由）
· 批量批准 + 例外上报（噪音来自粒度太细，不是人类介入）
· 批准本身进审计
```

### 模块5：审计（映射到 OTel GenAI）
```
★ 用 OpenTelemetry GenAI 语义约定（gen_ai.*），不自己定

标准字段（9 个）：
· 用户身份 / 智能体身份 / 租户 / 工具 / 动作 / 资源
· 策略决策 / 时间戳 / 请求哈希

v3 追加 2 个：
· policy_version（策略版本，事后可复现判定）
· agent_capability_hash（能力快照，防事后扩权）

要求：
· 请求哈希覆盖：输入 + 策略 + 能力（不只请求体）
· 写入不可变存储（append-only / 透明日志）
· 智能体身份与用户身份分开记（委托链可追溯）
```
