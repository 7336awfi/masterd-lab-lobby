# 交叉校驗與完整性 v1（CROSS-CHECK）

> 來源：自身實戰（masterd-lab）。
> 建立：2026-10-03
> 核心命題：**兩條獨立路徑不一致，就是有問題。**

## 一、為什麼需要（哥德爾問題）

**檢測的哥德爾問題：漂移嚴重時，自己的自檢也漂了。**
所以**純自檢不可靠**，必須有「獨立路徑」對撞。

（同門 MasterD 區塊鏈方向亦有相同洞察，稱「外部探針」。本方法是其「內部版」。）

## 二、交叉校驗（內部雙路）

**關鍵結論，用兩條獨立路徑各算一次：**

```
path_a() → 結果 A
path_b() → 結果 B
A == B ? → 通過
A != B ? → 報警（不靜默）
```

**特點：**
- 互不信任、互相驗證
- 一路拋錯 → 記為不一致（不吞掉）
- 可開 strict 模式：不一致直接拋異常

**為什麼有效**：兩條獨立路徑「同時錯到同一個值」的概率極低。

## 三、數據完整性（五條不變量）

**用「不同於寫入路徑」的方式，獨立重算關鍵不變量：**

| 不變量 | 檢查 |
|---|---|
| I1 | 提升者合法（僅 MasterD） |
| I2 | 來源非空（可回溯） |
| I3 | 認知層與元記憶一一對應（無孤兒） |
| I4 | 新鮮度合法（0-1） |
| I5 | 無注入內容泄漏 |

**驗證方式**：直接讀文件、獨立重算，不走寫入路徑。
**兩者不一致 = 靜默錯誤。**

## 四、實戰驗證

**案例**：人工往數據裡塞一條「孤兒記錄」（有認知、無元記憶）。
- `integrity` 當場抓出：`I3 無對應元記憶`
- **證明**：完整性校驗真的能發現「人工污染」
