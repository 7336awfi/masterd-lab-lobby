## 〇、射程声明（v2 新增，必须最先读）

**本方案解决的是「越权不可发生」，不解决「意图可验证」。**

```
· "意图可验证"（证明 agent 想干的 = 它干的）→ 开放语义下不可判定
  → 本方案【不解决】它。这不是本方案的失败，是问题本身不可判定。
· "越权不可发生"（任何实际动作都落在授权集合内）→ 可判定
  → 本方案【解决】它。
```

**射程外（明确不承诺）：**
```
❌ 授权范围内的恶意/意外行为（agent 被注入后在授权内作恶）
❌ 意图的语义正确性
❌ 私钥被窃取后的冒充（除非硬件级且无侧信道）
❌ 量子攻击
```

**划清射程，不是回避——是把「能解决的」和「不能解决的」说清楚。**

## 一、核心认知（v2 修正措辞）

| 概念 | 性质 | 能否做到 |
|---|---|---|
| 「意图可验证」 | 语义问题（开放集） | ❌ 不可判定 |
| 「越权不可发生」 | 集合包含问题 | ✅ 可判定 |

**修正（v1 → v2）：**
- v1 说「越权不可发生 ✅ 有解」→ **过度**（那是持续逼近，不是可达状态）
- v2 说：「越权不可发生 = **持续逼近的目标**，需要对抗性扩展」

## 二、技术分层（按威胁模型）

| 层 | 内容 | 成熟度 |
|---|---|---|
| **密码学层** | 密钥、签名、nonce、防重放 | 🟢 成熟 |
| **信任锚层** | 公钥来源、可问责委托 | 🟡 难（治理+工程） |
| **语义层** | 意图验证 | 🔴 不可判定 |

**关键：信任锚不是缺陷，是地基（任何系统都有不可再问的根）。**

## 三、推荐架构（Capability 模型）

```
【核心原则】
资源方持有 root key；签发方只能「衰减」不能「扩权」；
约束在「资源方」独立验证；agent 完全不可信。

【流程】
1. 授权方签发 capability token（含约束）
2. Agent 持 token 请求动作
3. 资源方独立验证：token 有效性（签名）+ 动作在约束内（本地策略）
4. 通过 → 执行；不通过 → 拒绝
```

**参考实现：Macaroon（可衰减、不可扩权）**

## 四、五个模块（v2 修正）

### 模块1：密钥与签名
```
· Ed25519 密钥对（每个 Agent 唯一）
· 私钥保管：★ 必须「硬件/进程级隔离」（v2 强调）
  · 优先：TPM / SE / TEE
  · 次选：独立进程 + 权限隔离
  · ❌ 禁止：「本地文件 + 权限位」（注入的 agent 同权限，照样读）
· 签名 payload = from|action|target|amount|nonce|ts
· 收方验签
```

### 模块2：防重放
```
· nonce（一次性）+ 时间戳
· 收方维护「已见 nonce 去重表」
· 时间窗（超 X 分钟无效）
· ⚠️ 前提：时间源可信（时钟被操纵 = 时间窗失效）
```

### 模块3：授权约束（Capability）★核心
```
· 授权 = 「动作集合」（不是「身份绑定」）
· 约束维度：**枚举**（v2 改词），不是「穷举」
  · amount / target / action / 时间窗 / 次数 / 频率
· ★ 明确声明：约束维度是【开放集】
  · 本方案覆盖「已枚举的 N 类」
  · 未枚举类别不在承诺范围内
  · 附「未覆盖类别清单」（哪怕为空）
· 约束在「资源方」验证（agent 侧不可信）
```

### 模块4：撤销与轮换（v2 拆两节）
```
【长寿命 agent】
· 依赖撤销传播（CRL/OCSP）
· 需评估「传播延迟 vs agent 寿命」的比例
· 主论证（撤销是这道防线）

【短寿命 agent】
· 不依赖撤销（撤销到达前已死）
· 依赖 TTL 自然过期
· 边界说明（不是替代，是并列机制）
```
**★ 归位规则：长寿命 = 机制论证（放设计章节）；短寿命 = 适用边界（放适用场景章节）。**

### 模块5：审计（v2 升级为 P0）
```
· 不是「落日志」，是「异常检测 + 维度反推」
· 关键：用审计「反推漏了哪个约束维度」→ 持续扩展
· 前提：日志本身不可篡改（存哪、谁能改，必须定义）
```

## 六、未说清的假设（v2 交代）

```
① 资源方可信性 → 需单独成章讨论（资源方被攻陷 = 约束执行点没了）
② 授权方可信性 → 授权方是信任根（它烂了全烂）
③ 约束动态性 → 本方案只处理「静态约束」，动态约束是缺口
④ 动作可枚举性 → 开放动作空间（如自然语言）无法用白名单
⑤ 时间同步 → 撤销/TTL/审计全依赖时间，时间源必须可信
⑥ 私钥保管 → 已强调隔离
⑦ 审计不可篡改 → 必须定义存储与权限
```

## 七、核心认知总结

```
1. 「意图可验证」不可判定 → 不追，用「越权防范」替代
2. 「越权不可发生」是「持续逼近」，不是「可达状态」
3. 约束维度是【开放集】→ 只承诺「已枚举」，不承诺「穷举」
4. 信任锚是地基，不是缺陷
5. 私钥保管必须「硬件/进程隔离」（否则前面全白搭）
6. 审计是 P0（它是「发现漏维度」的唯一机制）
7. 任何方案都有天花板（纯密码学防不了 prompt injection）
```
