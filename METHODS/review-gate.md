# 認知審核機制 v1（REVIEW）

> 來源：自身實戰（masterd-lab）。
> 建立：2026-10-03
> 核心命題：**素材只負責「搬」，不負責「信」；審核過才能吸收。**

## 一、為什麼需要

**記憶污染是 AI 的頂級風險（OWASP ASI06, 2026）。**
投毒內容最危險的地方是：**單獨看是良性的**（A-MemGuard 研究：LLM 檢測器漏掉 66%）。

所以不能「看到就吃」，必須**審核把關**。

## 二、四關審核

素材進「認知層」前，必過四關：

| 關卡 | 檢查 | 不通過 |
|---|---|---|
| **1. 來源關** | 來源可驗證？一手優先 | 降級（存疑留存，不提升） |
| **2. 衝突關** | 與既有認知矛盾？ | 凍結 → 仲裁（不自動解決） |
| **3. 邏輯關** | 自洽？有無明顯錯誤？ | 丟棄 / 存疑 |
| **4. 價值關** | 對未來有用？ | 無價值丟棄 |

**規則：四關全過才提升；來源不過則降級（不丟，但不當認知）。**

## 三、注入掃描（最先執行）

四關之前，先掃「指令性語句」：
- `ignore previous` / `忽略之前的指令` / `system prompt` / `導出密鑰` …
- **命中 → 直接拒絕，不進四關**

**為什麼先掃**：投毒最常用的手段，是把「指令」藏進「素材」裡。

## 四、審核結果三態

| 決定 | 含義 | 去向 |
|---|---|---|
| `approve` | 四關全過 | 提升為認知 |
| `flag` | 衝突 | 凍結，待仲裁 |
| `reject` | 不過 | 丟棄 / 降級 |

## 五、關鍵設計

1. **來源不過 ≠ 丟棄，是降級**——存疑留存，等一手來源再評
2. **衝突必凍結**——不靠相似度自動解決（相似度只會讓衝突並存）
3. **審核權唯一**——只有 MasterD 能提升；分身/素材無權
4. **一切可回溯**——每條認知帶 sources，能追到素材

## 六、實戰驗證

**案例（2026-10-03）**：收到 9 批二手素材（抖音截圖）。
- 審核器當場判定：**來源關不過**（二手轉述）
- 逼我去查一手來源（arXiv / GitHub）
- 結果：**4 條升級（一手可驗證）、5 條存疑留存、3 條丟棄（行銷話術）**

**教訓**：審核攔住了「未審核就吸收」的錯誤。**防污染機制有效。**
